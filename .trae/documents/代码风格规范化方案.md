# 全工程 C 代码风格规范化方案（L1 纯排版）

## 背景与目标

工程自有代码（User/、Navi/、Peripheral/）存在两类历史来源的风格差异：Navi 模块为 A7 平台移植代码（Tab 缩进、`(*p).x` 解引用），User/+Peripheral/ 为本项目原生代码（4 空格缩进、`p->x`）。本次规范化在**业务行为 100% 不变**前提下，统一纯排版层面的风格分歧，不涉及任何标识符重命名与语句结构调整。

**已确认的决策**：
- 依据：工程多数派风格 + 通用嵌入式 C 规范
- 深度：L1 纯排版（不改标识符、不改语句结构）
- 缩进：维持分区（Navi/=Tab，User/+Peripheral/=4 空格），仅消除区内少数派
- 超长行：>120 列拆分为多行

**范围边界**：仅 User/、Navi/、Peripheral/ 下的自有 .c/.h；Library/、CMSIS/、project/.cmsis/ 等第三方代码一律不动。

## 规范化规则集（执行标准）

- **R1 缩进分区统一**：Navi/ 区内少数派文件 4 空格缩进 → Tab（1 Tab = 一级缩进，行内对齐空格保留）；User/+Peripheral/ 区内逐文件排查 Tab 混入 → 4 空格。仅转换行首缩进字符，不动行内内容。
- **R2 指针声明星号归位**：统一为 `type *ptr`（星号靠变量侧）。`struct X* p` → `struct X *p`；`float* x` → `float *x`。同步覆盖 .h 声明与 .c 定义（纯空格改动，不影响编译语义）。依据：多数派风格，且符合"星号与变量名相连避免 `float* a, b;` 歧义"的通用规范。
- **R3 超长行拆分（>120 列，58 处）**：按三类处理——
  1. 函数定义签名行：从参数逗号处断行，续行缩进与首个参数对齐；
  2. 批量变量声明行：按语义分组断行，续行与原行首对齐；
  3. 函数调用+行尾注释行：在参数逗号处断行，`//` 注释整体移至末行尾或独占续行，保证注释内容不丢失、不截断。
- **R4 多余空行压缩**：函数体内连续 ≥2 空行压缩为 1 行（仅 navi_time_sync.c 4 处 + 执行期全量复查）；文件首尾、函数之间的既有空行格局不动。
- **R5 验收保持项**：行尾空格维持 0；大括号 Allman 风格不动；关键字间距不动；`(*p).x` 不改；标识符一律不改。

## 风险控制

- 脚本转换仅限两类安全模式：行首缩进字符、指针声明星号两侧空格；不触碰字符串字面量、宏定义体、注释内容。
- 超长行拆分逐处人工进行，断点只选参数逗号/运算符边界，保证表达式语义不变。
- 每批改完立即编译，尺寸基线不符即回退该批。
- 完成后输出变更说明，明确列出：改动文件清单、每类规则的改动处数、未改动项（R5 清单）。
